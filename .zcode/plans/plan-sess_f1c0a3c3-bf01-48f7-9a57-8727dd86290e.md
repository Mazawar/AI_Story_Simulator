# 阶段 2 · 引擎模式实施计划

## 目标与验收

把"数值/面板/锚点/剧情推进"从提示词自律改为代码强制，LLM 只做叙事与结构化裁决。验收标准：

1. **数值守恒**：脚本化 20 回合会话，所有数值变化都来自白名单指令且可对账，无凭空增减；
2. **面板真数据**：「修士」「任务」「提示」「降级面板」由引擎从真实状态渲染（不再问 LLM）；
3. **首回合 < 60 秒**：上下文组装后每回合约 9k token（对比直通模式 12k+ 全量）；
4. **防剧透结构化**：未触发锚点的揭晓内容不可能出现在 LLM 上下文里（结构保证，非提示词约束）；
5. 全部测试通过 + 冻结 EXE 实测引擎模式一整局。

## 里程碑（每个独立可验证，依次交付）

### M1 · 数值体系解析 + 裁决协议（根治数值漂移）

- `app/pack/numeric.py`：确定性解析数值体系章节 → `NumericSchema`（存 `storys.metadata_json`）：
  - 境界阶梯（练气13层 / 筑基初中后…）、寿元上限（练气100/筑基200/结丹500/元婴1000/化神2000）；
  - 时间流规则（练气+1层扣1年、大境界突破扣10/30/80/200年、事件扣年表）——凡人包里这些是"写死"条款，正则可解析；
  - 灵石币制（下/中/上/极品 1:100）、灵根速度系数、防刷子衰减参数；
  - 无数值章节的包（剑来）回退到内置通用修仙模板。
- `app/core/rules.py`：`EffectProcessor` 白名单指令执行器——`{"deltas":[{ref,op,v,reason}], "item_add/remove", "set_flag", "affinity", "anchor_trigger", "choices":[…]}`，校验边界（寿元≥0、境界上限）、防刷子（同来源收益哈希重复→递减）、禁改项（模型不能直接写寿元，只能走突破/事件规则）。
- **裁决协议**：LocalBackend 增加 GBNF 语法约束生成（llama-cpp `grammar` 参数），强制输出 `{"narrative":…, "effects":…}` JSON；远端走 json 指令 + repair_json 重试。
- 测试：伪 LLM 注入合法/非法指令 → 状态断言；20 回合守恒测试。

### M2 · 面板引擎渲染（根治交互面板）

- 引擎每回合从真实状态组装 TurnPayload：播报条（含剧本包规定的"旧→新"变化显示）、deltas（前端浮动动画）；
- 触发词「修士/任务/提示」由引擎直接产出面板块（属性/物品/任务列表），不进 LLM；「降级/恢复面板」成为视图密度开关；
- 前端：属性面板抽屉（境界进度条、寿元、灵石）、物品卡列表、deltas 浮动动效。
- 测试：状态变更 → 面板字段断言。

### M3 · 锚点系统 + 剧情线（根治剧情漂移）

- `app/pack/anchors.py`：解析剧情锚点（凡人事件时间表 ①-⑤ + 剑来 ①-⑨ 编号列表）、揭晓点 bullets → `story_anchors` 表（表已建好，含 trigger_json/spoiler_level/source_refs）；
- 条件 DSL（安全 JSON 子集，仅引擎求值）：`{"type":"turn_gte"|"flag"|"realm_gte"|"location"|"depends_on", …}` + all/any 组合；解析不出的锚点降级为"轮次窗口 + 相邻依赖"启发式；
- 身份线（凡人四选一的 ①-⑤ 节点链）作为每局状态机推进；
- 「本章结束」→ 引擎从 turns 表计算章节结算面板（本段数值增减/事件/关系变化统计）。
- 测试：条件求值器全覆盖 + 剧透隔离（未触发锚点的 reveal_text 断言不出现在组装上下文）。

### M4 · 上下文组装器 + 滚动摘要（根治等待时间）

- `app/ai/context_assembler.py`：稳定前缀（文风合同+世界观压缩+约束精选，KV 缓存友好）+ 动态后缀（状态摘要 + 相关角色卡按近期出场筛选 + 最近 N 轮 + 滚动摘要 + 邻近锚点元信息），目标 ≤9k token；
- 滚动摘要：每 10 回合把早期剧情压缩为 ≤300 字存 `playthroughs.rolling_summary`（migration v2 加列）；
- 角色卡筛选：近期轮次提及的参与者优先，全文卡截断。
- 测试：token 预算断言 + 摘要触发。

### M5 · 整合与交付

- `EngineSession`（mode='engine'）接入 API：剧本包解析出数值体系或锚点即默认引擎模式，否则自动回退直通；续玩路径适配；
- 前端整合（deltas 动效/面板抽屉/结算弹窗）；
- migration v2（rolling_summary 列）+ 全量测试 + `make_exe` 重打 + 冻结环境实测一整局。

## 关键风险与对策

- **GBNF 与 Qwen3 兼容**：M1 第一件事先做语法约束冒烟，失败则退回"json 指令 + 修复重试 + 结构校验拒收"三层兜底；
- **数值/锚点解析覆盖不全**：所有解析器都带默认模板回退（通用修仙模板），引擎模式不因包格式缺失而不可用；
- **1.7B 裁决质量**：裁决 JSON 字段极简化（模型只填叙事+增量），复杂规则全在引擎侧。

## 明确不做（本阶段）

- 嵌入/RAG（阶段 3 与小说拆解一起做）、剧本包编辑器 UI、在线 API 模式的引擎模式差异适配（协议相同，顺带支持）。
